GitHub Actions

This is the supported CI shape for consumer repositories that use nGitDB to turn generated JSON into reviewable pull requests.

Install Path

Install nGitDB as a package dependency in the consumer repository:

npm install ngitdb

Commit the resulting package.json and lockfile, then use npm ci in GitHub Actions. Cloning this repository directly from a private workflow is a development workflow for nGitDB itself, not the supported consumer install path.

If your organization mirrors packages into a private registry or GitHub Packages, install the published package from that registry. The application import remains:

import { createGitDB } from "ngitdb";

Required Workflow Permissions

The GitHub backend uses the GitHub REST API to read contents, create or resume a session branch, create a commit, update the branch ref, and create or update a pull request.

Use the smallest required GITHUB_TOKEN permissions:

permissions:
  contents: write
  pull-requests: write

The repository or organization Actions settings must also allow GitHub Actions to create pull requests.

The nGitDB runtime reads GITHUB_REPOSITORY and GITHUB_TOKEN from the process environment when owner, repo, and token are omitted:

const db = createGitDB({
  repositoryRoot: process.cwd(),
  backend: { type: "github" },
  baseBranch: "main",
  resources: {
    companies: {
      fileName: "company.json",
      ownership: {
        legalName: "human-owned",
        machine: "machine-owned",
      },
    },
  },
});

In a workflow step, expose the Actions token explicitly:

env:
  GITHUB_TOKEN: $

Minimal Workflow

This example assumes Python writes a merged JSON document to tmp/company.json, and a Node script applies the machine-owned fields through nGitDB.

name: Update company data

on:
  workflow_dispatch:

permissions:
  contents: write
  pull-requests: write

jobs:
  update:
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: npm

      - run: npm ci

      - name: Build merged JSON
        run: python scripts/build_merged_json.py --output tmp/company.json

      - name: Create nGitDB pull request
        run: node scripts/apply-ngitdb-update.mjs tmp/company.json
        env:
          GITHUB_TOKEN: $

Minimal scripts/apply-ngitdb-update.mjs:

import { readFile } from "node:fs/promises";
import { createGitDB } from "ngitdb";

const inputPath = process.argv[2];
const merged = JSON.parse(await readFile(inputPath, "utf8"));

const db = createGitDB({
  repositoryRoot: process.cwd(),
  backend: { type: "github" },
  baseBranch: "main",
  resources: {
    companies: {
      fileName: "company.json",
      ownership: {
        legalName: "human-owned",
        machine: "machine-owned",
      },
      validate: (document) => {
        const issues = [];
        if (typeof document.legalName !== "string" || document.legalName.length === 0) {
          issues.push("legalName must be a non-empty string");
        }
        if (document.machine === null || typeof document.machine !== "object" || Array.isArray(document.machine)) {
          issues.push("machine must be an object");
        }
        return issues;
      },
    },
  },
});

const resourcePath = `companies/${merged.id}`;

await db.startSession(merged.id);
await db.patch(resourcePath, {
  machine: merged.machine,
});
await db.commit(`Update company data for ${merged.id}`);
await db.createPullRequest({
  title: `Update company data for ${merged.id}`,
  body: "Generated by the nGitDB GitHub Actions workflow.",
});

Reusable Workflows

For a reusable workflow, keep the same token contract: the called workflow must run with contents: write and pull-requests: write, and the Node step must receive GITHUB_TOKEN.

Caller workflow:

name: Update company data

on:
  workflow_dispatch:

jobs:
  update:
    uses: your-org/automation/.github/workflows/ngitdb-update.yml@main
    permissions:
      contents: write
      pull-requests: write
    secrets: inherit

Called workflow:

name: nGitDB update

on:
  workflow_call:

jobs:
  update:
    runs-on: ubuntu-latest
    permissions:
      contents: write
      pull-requests: write

    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: "22"
          cache: npm

      - run: npm ci

      - run: node scripts/apply-ngitdb-update.mjs tmp/company.json
        env:
          GITHUB_TOKEN: $

Use secrets: inherit only when the called workflow also needs caller secrets other than the default GITHUB_TOKEN. nGitDB itself does not require a custom secret when it can use $ with the permissions above.

Existing Versus New Resources

patch(resourcePath, patchDocument) updates an existing JSON resource. With the GitHub backend, nGitDB reads the resource file from the active session branch before applying the patch. If the file is missing, the operation fails with ResourceNotFoundError.

For V1, create seed resource files before using nGitDB updates, for example:

data/companies/acme-gmbh/company.json

After the file exists on the base branch, nGitDB can update it through session branches and pull requests. If a session branch already exists, startSession(...) resumes it instead of creating a duplicate branch; if an open pull request already exists for the same session branch and base branch, createPullRequest(...) updates that pull request.
